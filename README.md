**把每天要做的事排好，讓日序在適合的時間提醒你。**

由 **Casanova** 製作的 Windows 桌面私人秘書。將行程、待辦與提醒放在同一個地方，依自己的步調安排工作與生活；繁體中文介面、24 小時制，資料自動儲存在本機，使用時不需要登入或連線。

## 為什麼做日序

有些事情需要準時開始，有些只想先記下來；每天都會做的事，也不想每天重新輸入。日序讓你把這些日常安排整理在同一張時間表上：

- **不想忘記接下來的安排**：替行程設定開始前或結束前提醒，到點顯示小卡並播放提示音。
- **想看清楚今天的時間分配**：以 `15:00 - 16:00` 顯示時段，也能切換週／月檢視查看安排。
- **常有固定的生活習慣**：用常用事項快速填入冥想、健身、用餐等名稱，搭配重複行程減少輸入。
- **計畫會隨時調整**：自由修改日期、時間、持續多久與提醒；提前完成時直接勾選。
- **想讓清單留在桌面旁邊**：切換迷你視窗，或收進系統匣繼續接收提醒。

## 目前狀態

目前版本為 **1.0.5**，專案仍在私人開發階段，尚未正式公開發布。儲存庫提供原始碼、必要素材、測試與文件，目前可依下方步驟自行建置。

支援目標為 **Windows x64**，目前實測環境為 **Windows 11 x64**。尚未提供 macOS、Linux 或原生 Windows ARM64 安裝包。Windows 安裝檔尚未簽章，也沒有自動更新功能。

## 功能概要

| 功能 | 可以做什麼 |
| --- | --- |
| 日／週／月檢視 | 預設查看今日時間表，也能查看其他日期與整週、整月安排。 |
| 行程與待辦 | 排定開始與結束時間，或先記成沒有時段的待辦，之後再補上時間。 |
| 彈性時間輸入 | 小時、分鐘分開操作，支援手動輸入、下拉選擇、持續時間連動與跨日行程。 |
| 常用事項 | 自訂常用名稱，輸入時篩選、從選單選取，選取後仍可修改。 |
| 重複行程 | 每天、每週或每週指定多個星期幾，可設定截止日期。 |
| 多個提醒 | 針對開始或結束設定提前 5 分鐘、10 分鐘、自訂分鐘數或當下提醒，也能關閉。 |
| 完成與進行中 | 時段內的未完成行程會標示進行中；任何時間都能勾選完成或取消完成。 |
| 直接刪除 | 每列右側依序為編輯、垃圾桶；刪除只影響所選的那一次。 |
| 迷你視窗 | 精簡顯示今日清單、勾選完成，可切換保持最上層。 |
| 背景執行 | 關閉視窗後留在系統匣，安裝版可於登入 Windows 後自動在背景啟動。 |
| 本機儲存 | 行程、常用事項、設定與提醒紀錄保存在本機 SQLite，應用程式離線可用。 |

## 如何使用

### 1. 新增第一筆行程

1. 點選 **新增事項**。
2. 輸入事項名稱，或點右側箭頭選擇常用事項；清單以外的名稱也能直接使用。
3. 選擇 **安排時段**，填入開始與結束日期、時間。
4. 依需要調整持續分鐘、重複規則、提醒與備註。
5. 按 **新增事項** 儲存。

例如，建立「去健身」，安排 `15:00 - 16:00`，設定「開始前 10 分鐘」與「開始當下」，就會在 14:50 與 15:00 收到提醒。

### 2. 輸入時間與跨日安排

| 欄位 | 輸入方式 |
| --- | --- |
| 日期 | 手動輸入，或使用日期選擇器。 |
| 小時 | 下拉選單為 `00～24`，也能手動輸入。 |
| 分鐘 | 下拉選單為 `00、05、10…55`；手動輸入可用 `00～59`，例如 `09:07`，不會取整。 |
| 持續時間 | 選擇常用分鐘數或自行輸入，與結束時間連動。 |

`24:00` 代表所選日期的**隔天 00:00**，`24:05` 不接受。跨午夜時，將結束日期設為隔天；結束時間必須晚於開始時間。時間表會將起訖時間放在同一行，跨日另標註結束日期。

時段重疊會顯示提示，但仍可儲存；前一件在 16:00 結束、下一件在 16:00 開始，不算衝突。

### 3. 先記成待辦

還沒決定時間時，選擇 **先記成待辦**，填入日期與名稱即可。待辦會另列，**沒有時段的待辦不發提醒**；之後按編輯，切換為安排時段，就能轉成行程。

### 4. 設定常用事項與重複行程

在 **偏好設定 → 常用事項** 新增、修改、刪除或上下調整名稱順序，完成後按 **儲存常用事項**。初始項目包含冥想、去健身、早餐、午餐、晚餐與洗澡。

常用事項只填入名稱，不會改動時間或提醒。臨時輸入的名稱不會自動加入常用清單，修改常用清單也不影響既有行程。

若同一件事會固定發生，可在事項編輯視窗選擇 **每天** 或 **每週／指定星期**，並選填截止日期。編輯既有重複行程時，可選 **僅本次** 或 **本次及未來**。

「本次及未來」會更新後續規則，保留此前行程；未來原有的個別改期會被這次批次設定取代，符合新規則日期的完成狀態保留。

### 5. 完成、編輯與刪除

- **完成**：勾選事項左側方框，事項與時段會加上刪除線、淡化並標示已完成，位置保持不變；尚未開始也能提早完成。
- **取消完成**：再點一次方框，不跳確認視窗；只恢復未來的提醒，不重播已過去的提醒。
- **編輯**：點列右側的編輯按鈕，修改後按 **儲存變更**。
- **刪除**：點最右側的垃圾桶，直接刪除所選那一次，**不會跳出確認或刪除範圍選擇**；重複行程的其他日期保留。編輯視窗內的垃圾桶也只刪除當次。

完成會取消當次後續提醒，並解除進行中標示。已過期的事項不會自動改期或刪除。

### 6. 設定與測試提醒

新行程預設為 **開始前 10 分鐘＋開始當下**，結束提醒預設關閉。每筆行程都可獨立調整；在 **偏好設定 → 一般設定** 可修改之後新增行程的預設提醒，按 **儲存設定** 套用。

正式提醒使用 **日序小卡＋提示音**：

- 小卡顯示在滑鼠所在螢幕的右下角，避開工作列，不搶鍵盤焦點。
- 顯示事項名稱、時段與提醒原因，約 10 秒後自動關閉；也能手動關閉或點擊開啟對應事項。
- 同批提醒合併顯示，播放一次聲音；主視窗縮小或收進系統匣時仍可提醒。
- 聲音依電腦音量、輸出裝置與靜音設定，不依賴 Windows 通知音效。

初次使用時，到 **偏好設定 → 一般設定 → 測試提醒**，確認自己看得到小卡、也聽得到聲音。

### 7. 使用迷你視窗與背景執行

標題列可切換完整／迷你視窗，圖釘按鈕切換保持最上層。視窗可拖曳、縮放，兩種模式分別保存位置與尺寸；迷你模式可勾選完成，編輯時會切回完整模式。

按視窗右上角關閉按鈕，程式會**收進系統匣繼續提醒**。要完全停止，請右鍵系統匣的日序圖示，選擇完全結束。

安裝版預設於登入 Windows 後在背景啟動，可在偏好設定關閉；開發版不註冊登入啟動。

## 安裝與啟動

### 使用安裝檔

目前儲存庫未附安裝檔，可先依下一節自行建置。之後若發布安裝檔，會放在 [GitHub Releases](https://github.com/Casanova033822/daybook-secretary/releases)。

取得對應版本的 `Daybook-Setup-1.0.5.exe` 後，依安裝精靈操作，再從桌面或開始功能表開啟日序。**使用安裝版不需要 Node.js、npm 或另裝字體**；同一應用程式的覆蓋更新會沿用原本資料。

本版安裝檔尚未簽章，Windows 可能顯示未識別發行者或 SmartScreen 警告。建置時產生的 `SHA256SUMS.txt` 可用於核對檔案完整性，但不能代替簽章或證明發行者身分。

### 從原始碼啟動

準備 Windows x64、Git、**Node.js 24.x（含 npm）**，並登入有權限存取私人儲存庫的 GitHub 帳號：

```powershell
git clone https://github.com/Casanova033822/daybook-secretary.git
cd daybook-secretary
npm ci
npm run build
npm start
```

開發時使用：

```powershell
npm run dev
```

首次安裝依賴及打包需要網際網路；應用程式本身離線可用。使用 `npm ci` 依照 `package-lock.json` 安裝，無須另外安裝 SQLite、Python 或 Visual Studio C++ 工具。

GitHub 的 **Code → Download ZIP** 取得的是原始碼，仍需上述建置步驟。Clone 或下載原始碼不會同步原裝置的個人行程。

## 資料、隱私與使用限制

資料預設位於：

```text
%APPDATA%\日序\daybook.sqlite
```

行程、備註、常用事項、完成狀態、提醒紀錄與偏好設定儲存在本機。資料庫**未加密**，同一 Windows 帳號或系統管理員可以讀取。程式不收集遙測、不上傳行程，也不提供雲端同步；原始碼儲存庫不包含個人行程資料。

目前使用時需要留意：

- 使用 Windows 本地日期與時間；重複行程維持當地鐘面時間，不存在的日光節約時間會在輸入時拒絕。
- 睡眠、關機或完全結束程式時不會準時提醒，也不會主動喚醒電腦。啟動或喚醒後，當天尚未完成事項的漏掉提醒會合併成摘要，過往日期不補發。
- 新建立或改動的提醒不會補發已過去的時點；完成、改期或刪除後，相關提醒會重新計算。
- 小卡顯示失敗會有限次重試；音效失敗另行記錄，不重複顯示已成功的小卡。
- 若小卡已顯示但提醒紀錄無法寫入，程式會在本次執行期間避免重複彈卡並重試儲存；若尚未寫入就結束或斷電，重啟後仍可能補發。
- 目前沒有倒數計時、稍後提醒、手動備份／還原介面、歷史統計、帳號或跨裝置同步。

回報問題時請勿附上個人資料庫、金鑰、未遮蔽的行程截圖或日誌。更多說明見 [SECURITY.md](SECURITY.md)。

## 開發與測試

### 技術組成

| 技術 | 用途 |
| --- | --- |
| Electron | Windows 桌面視窗、系統匣與背景提醒。 |
| React、TypeScript、Vite | 介面、型別與前端建置。 |
| FullCalendar 標準版 | 週／月檢視。 |
| Node.js `node:sqlite` | 主程序管理本機資料庫。 |
| electron-builder | 建置 Windows NSIS 安裝程式。 |

主程序負責資料與提醒；renderer 使用 sandbox、context isolation 與受驗證的 IPC。正式版只載入內附頁面並阻擋外部網路請求，詳見安全說明。

畫面優先使用本機 Noto Sans TC，沒有時使用微軟正黑體；專案不分發字型檔。

### 常用指令

| 指令 | 用途 |
| --- | --- |
| `npm run dev` | 啟動開發模式。 |
| `npm run typecheck` | 檢查前端與 Electron 程式型別。 |
| `npm test` | 執行單元與安全測試。 |
| `npm run build` | 建置介面與主程序。 |
| `npm start` | 啟動已建置的應用程式。 |
| `npm run test:desktop` | 驗證開發版桌面互動。 |
| `npm run dist` | 產生第三方聲明、建置 Windows x64 安裝檔並執行成品檢查。 |
| `npm run test:release` | 驗證打包後的應用程式。 |
| `npm run export:source` | 依白名單匯出原始碼，不包含個人資料與建置成品。 |

打包輸出位於 `release/`，包含安裝檔與 `SHA256SUMS.txt`；首次打包會下載 Electron 和 NSIS。原始碼匯出工具不覆寫既有同版本匯出目錄。

桌面測試需要 Windows 桌面工作階段，使用獨立資料目錄，會實際顯示提醒小卡及播放音效，截圖存放於 `test-results/`。可另外執行：

```powershell
node tests/layout.mjs
node tests/delete-row.mjs
node tests/editor-review.mjs
node tests/window-storage.mjs
node tests/reminders.mjs
```

以上分別涵蓋版面與字體備援、刪除當次、編輯草稿與競態、視窗設定儲存失敗，以及提醒排程；提醒測試約需 3 分鐘。打包版使用 `npm run test:release`，不要直接套用依賴 Electron 主程序偵錯介面的舊測試。

內附 [Windows build 工作流程](.github/workflows/windows.yml)，會測試、建置並保存安裝成品，不會自動發布 Release。人工仍需確認喇叭有聲、登入啟動、真實睡眠喚醒與多螢幕行為；自動測試的播放完成紀錄不能證明使用者實際聽到聲音。
